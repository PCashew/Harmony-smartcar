# 2026-08-28 学习日志

## 今日主题

今天完成了 Hi3861 智能小车 SSD1306 OLED 的驱动、显示与动画实验。从最开始的文字和时钟显示出发，逐步实现动态小猫，并针对画面比例、屏幕方向、显示区域和动作自然度进行了多轮调整。最后完成 OpenHarmony 编译、HiBurn 烧录测试和 GitHub 版本归档。

## 1. Hi3861 与 OLED 的 I2C 通信

### 硬件与参数

| 项目 | 当前配置 |
| --- | --- |
| OLED 控制器 | SSD1306 |
| 屏幕分辨率 | 128×64，单色 |
| I2C 控制器 | I2C0 |
| SCL | GPIO9 |
| SDA | GPIO10 |
| I2C 速率 | 400 kbit/s |
| 写地址 | `0x78` |
| 命令控制字节 | `0x00` |
| 数据控制字节 | `0x40` |

程序先通过 `IoSetFunc` 将 GPIO9、GPIO10 复用为 I2C0，再调用 `I2cInit` 初始化总线。SSD1306 的初始化命令和显存数据最终都通过 `I2cWrite` 发出。

### 关键理解

I2C 只负责把字节可靠地送到 OLED，屏幕最终显示什么取决于 SSD1306 的寻址模式、页地址、列地址和图像数据。发送命令前要带 `0x00`，发送显存数据前要带 `0x40`，不能把两种数据混在一起。

## 2. SSD1306 页式显存与全屏显示

128×64 单色屏幕共需要：

```text
128 × 64 ÷ 8 = 1024 字节
```

程序使用 1024 字节帧缓冲区保存完整画面。SSD1306 将垂直方向每 8 个像素组织成一页，因此 64 行对应 8 页。设置像素时使用下面的映射关系：

```text
字节下标 = x + (y / 8) × 128
位掩码   = 1 << (y % 8)
```

刷新时依次选择第 0～7 页，每页写入 128 字节，才能覆盖整块屏幕。

### 今天遇到的问题

早期为了让图案“横过来”，曾把逻辑坐标和物理屏幕坐标混用，导致图像集中在 OLED 上半部分。这个问题并不是屏幕坏了，而是坐标变换后仍按错误的宽高或页数刷新。

最终方案始终以物理分辨率 128×64 建立帧缓冲区，所有坐标限制在 `x=0～127`、`y=0～63`，再按 8 页完整刷新。屏幕方向需要通过统一坐标变换处理，不能只交换宽、高常量。

## 3. 从文字显示到 16 帧小猫动画

最初版本使用 `SSD1306_ShowStr` 显示固定文字、日期和计时内容。在确认 I2C 与 OLED 驱动工作正常后，开始尝试动态图案。

最终版本使用像素、直线和加粗线段直接绘制猫咪轮廓，没有保存 16 张完整位图，而是用 16 组相位参数控制身体轻微起伏、左右爪位置和动作幅度。这种方式可以减少重复数据，也方便继续调整造型。

### 最终动画参数

| 参数 | 数值 |
| --- | ---: |
| 动画帧数 | 16 帧 |
| 单帧间隔 | 90 ms |
| 理论帧率 | 约 11.1 FPS |
| OLED 任务栈 | 2048 字节 |

造型调整过程中重点解决了以下问题：

- 放大头部，避免头小、身体过长。
- 缩短并圆化身体，让整体比例更接近参考图。
- 取消独立的细长脖子，让脸颊自然连接肩部。
- 重新设计爪子轮廓：一只爪子遮住鼻子，另一只在脸侧摆动。
- 通过身体和手部的小范围偏移形成连续动作，避免只在两个姿势之间生硬跳变。
- 使用 90 ms 刷新间隔，在流畅度、I2C 传输量和 CPU 占用之间取得平衡。

## 4. OpenHarmony 工程集成与编译

OLED 组件放在：

```text
applications/sample/wifi-iot/app/7.0_I2c_Ssd1306/
```

主要文件包括：

- `I2c_Ssd1306.c`：创建 OLED 线程并循环播放动画。
- `src/hal_bsp_ssd1306.c`：I2C 通信、SSD1306 初始化、帧缓冲和绘图函数。
- `include/hal_bsp_ssd1306.h`：驱动接口声明。
- `include/hal_bsp_ssd1306_fonts.h`：字符点阵数据。
- `BUILD.gn`：声明源文件和头文件目录。

在 app 的 `BUILD.gn` 中加入该组件后，使用下面的命令编译：

```bash
python build.py wifiiot
```

编译成功后生成 `Hi3861_wifiiot_app_allinone.bin`，可使用 HiBurn 烧录到 Hi3861。

## 5. HiBurn 烧录流程

1. 使用数据线连接智能小车与电脑，并关闭小车自身供电开关，避免重复供电。
2. 在 HiBurn 中选择 Hi3861 对应串口和待烧录的 `.bin` 文件。
3. 开始烧录，并按工具提示复位开发板。
4. 等待进度完成后点击 `Disconnect`。
5. 再按开发板 `RESET` 键运行新程序，观察 OLED 动画。

如果烧录成功但 OLED 没有显示，应依次检查供电、SCL/SDA 接线、I2C 地址、初始化返回值和串口日志，而不是立刻修改动画数据。
