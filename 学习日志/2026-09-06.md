# 2026-09-06 学习日志：红外循迹 v14.2 路线事件与受限主动居中

## 今日目标

在已回退到实车效果较好的 v14 基线上继续排查，不修改已经稳定的普通直线 FOLLOW 参数，重点处理：

1. 后续弯道突然原地掉头约 180°；
2. 固定赛道中的稳定误识别事件；
3. 弯道或岔路完成后容易偏离线路中心。

## 原因定位

v14 的路线表只有两个动作：

```c
{ DIR_LEFT, DIR_RIGHT }
```

前两个稳定触发事件消耗完路线表后，下一个事件会先进入终点横线判断。如果规定距离内没有检测到第二条横线，旧逻辑会把它转为死胡同，随后进入 `DEAD_END_PROBE -> TURN_BACK`，最终执行 180° 掉头。

因此，本次掉头并不是基础 FOLLOW 的 PWM 修正造成，而是“路线项耗尽后，单次事件超时被当成死胡同”的状态路径造成。

## 今日修改

### 1. 按实际稳定触发顺序扩展路线事件

路线动作调整为：

```c
{ DIR_LEFT, DIR_RIGHT, DIR_RIGHT }
```

每次触发输出：

```text
[ROUTE EVENT] index=? action=LEFT/RIGHT
```

这里的索引表示固定赛道中“第几个稳定识别出的路线事件”，不再只表示真实 Y 型岔路数量。

### 2. 禁止路线越界后自动掉头

当 `route_index >= ROUTE_COUNT` 且事件无法组成终点双横线时，固件现在会打印：

```text
[ERROR] ROUTE INDEX OVERFLOW index=?
```

随后停车并进入故障状态，不再自动进入 `TURN_BACK`。180° 掉头只允许由明确确认的死胡同触发，并增加：

```text
[TURNBACK] reason=DEAD_END_CONFIRMED
```

### 3. 增加严格受限的 ACTIVE_CENTER

主动居中只在路线事件成功转向并重新捕获支路后启动，普通 FOLLOW 中的 `WW` 不会触发。

工作过程：

1. 以低速前进弧线寻找另一侧传感器稳定检测 BLACK；
2. 用左右累计编码器里程差记录扫描量 `M`；
3. 反向低速前进弧线返回 `M / 2`；
4. 清空本次居中和搜索临时量，恢复基础 FOLLOW。

安全限制：

- 两个车轮始终只前进，不允许主动居中原地旋转；
- `CENTER_BASE_MM_S = 45`；
- `CENTER_DELTA_MM_S = 10`；
- 最大扫描量 `CENTER_MAX_METRIC_MM = 40`；
- 超时约 1.5 秒；
- 失败立即退出并打印 `[CENTER] fail`，不会无限搜索。

### 4. STM32 增加累计编码器里程查询

STM32 通信增加 `CMD_GET_ENCODERS (0x07)`，返回左右轮累计编码器毫米数，供 Hi3861 的主动居中计算使用。未修改 STM32 的 PI/PWM 控制参数。
