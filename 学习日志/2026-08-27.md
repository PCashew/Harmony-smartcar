# 2026-08-27 学习日志

## 今日主题

今天围绕智能小车的“感知—控制—通信”链路进行了学习和整理：先用定时器编码器接口获得车轮速度，再利用编码器反馈完成双轮电机闭环控制，同时梳理 OpenHarmony LiteOS-M 平台上的 Paho MQTT 移植代码。

## 1. 定时器编码器测速

### 完成内容

- 使用 TIM2 和 TIM3 的编码器接口模式分别采集左右轮正交编码器信号。
- TIM2 对应 PA0、PA1，TIM3 对应 PA6、PA7。
- 给输入捕获配置数字滤波，降低机械抖动和电气噪声对计数的影响。
- 按固定周期读取计数值，读取后将计数器清零，使每个采样周期的脉冲数可以直接反映轮速。
- 通过 USART1 周期输出左右轮测速结果，便于观察与标定。

### 关键理解

编码器模式会根据 A、B 两相信号的相位关系判断方向，因此计数值带有正负号。测速结果不仅与真实转速有关，还受到采样周期、编码器每转脉冲数和倍频方式影响。若要换算为转速，可以使用：

```text
转速 (r/min) = 采样脉冲数 × 60 / (每转计数 × 采样时间秒数)
```

固定采样周期非常重要；周期抖动会直接变成速度计算误差。

## 2. 双轮电机 PI 闭环控制

### 完成内容

- 使用 TIM4_CH1 和 TIM4_CH2 产生左右电机 PWM，频率约为 1 kHz。
- 通过方向引脚和 PWM 占空比实现前进、后退和停止。
- 以 50 ms 为一个控制周期，读取左右编码器反馈。
- 为左右轮分别实现带前馈的增量 PI 控制器：前馈用于克服静摩擦，PI 用于修正目标速度与实测速度之间的误差。
- 增加 PWM 限幅和禁止控制量意外跨零，避免误差过大时电机突然反向。
- 在起步阶段逐步提升目标速度，减小瞬时冲击和打滑。
- 同时考虑左右轮的瞬时速度差和累计行程差，对双轮同步进行纠偏。
- 实现定时前进与后退，并用不同 LED 效果指示运动状态。

### 参数记录

| 参数 | 当前值 | 含义 |
| --- | ---: | --- |
| 控制周期 | 50 ms | PI 更新及编码器采样周期 |
| 巡航目标 | 140 计数/周期 | 目标轮速 |
| 最小起步目标 | 40 计数/周期 | 速度斜坡起点 |
| `Kp` | 7.0 | 增量 PI 比例系数 |
| `Ki` | 0.8 | 增量 PI 积分系数 |
| 前馈 PWM | 4200 | 克服电机静摩擦的基础输出 |
| 单次前进/后退 | 8000 ms | 每个运动阶段持续时间 |

### 调参体会

调参时应先单独确认编码器方向和电机方向，再逐步增加目标速度。可以先关闭双轮同步修正，只调好每个车轮的速度 PI；单轮响应稳定后，再加入速度差和行程差修正。这样更容易判断振荡、超调或跑偏究竟来自单轮控制还是双轮耦合。

## 3. OpenHarmony LiteOS-M 与 Paho MQTT

### 学习内容

- 了解 Paho Embedded MQTT 的三个主要部分：MQTTPacket、C++ MQTTClient 和 C MQTTClient。
- 确认 OpenHarmony 相关适配集中在 `MQTTClient-C/src/liteOS/MQTTLiteOS.c`。
- 理解 MQTT 库移植的重点不是协议本身，而是为目标系统补齐网络连接、读写、超时和计时等平台接口。
- 认识 OpenHarmony 组件描述文件 `bundle.json` 与构建文件 `BUILD.gn` 在组件集成中的作用。

## 今日总结

编码器提供速度与方向反馈，PI 控制器根据误差调节 PWM，双轮同步修正进一步改善直线行驶；MQTT 则为后续上传小车状态、接收控制命令提供通信基础。三个部分连接起来后，可以形成从底层运动反馈到上层联网控制的完整雏形。
