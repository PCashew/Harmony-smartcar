## 二、VS Code 与 C 语言编译

今天继续使用 VS Code 进行 C 语言开发，并尝试直接通过 VS Code 终端编译程序。

在执行 GCC 编译命令时出现：

```text
gcc: error: main.c: No such file or directory
gcc: fatal error: no input files
compilation terminated.

经过检查，发现 GCC 本身可以正常使用，问题主要出现在当前终端目录。

编译器执行：

gcc main.c

时，会默认在当前工作目录寻找 main.c。如果当前目录不是源代码所在目录，就会出现找不到文件的情况。

因此，在使用 GCC 编译前，需要确认：

当前工作目录
        ↓
源代码所在目录
        ↓
main.c 是否存在
        ↓
执行 gcc 编译命令

这次排错也进一步熟悉了 VS Code 终端和项目目录之间的关系。

六、Git 基本操作流程

通过今天的操作，对 Git 日常使用流程进行了进一步整理。

修改或者新增文件后，可以使用：

git status

检查修改状态。

然后：

git add .

将修改加入暂存区。

再执行：

git commit -m "更新内容"

创建本地提交。

最后：

git push

将提交推送到 GitHub。

完整流程为：

修改文件
   ↓
git status
   ↓
git add .
   ↓
git commit
   ↓
git push
   ↓
GitHub

以后对 harmony-smartcar 进行日常开发时，可以按照这个流程进行版本管理。

七、main 与 master

今天还了解了 Git 中 main 和 master 的区别。

main 和 master 都是 Git 分支名称，本身没有功能上的本质区别。

早期 Git 创建仓库时通常使用：

master

作为默认分支。

现在 GitHub 新建仓库通常使用：

main

作为默认分支。

目前 harmony-smartcar 使用的是：

master

本地与远程的对应关系为：

本地 master
     ↓
origin/master
     ↓
GitHub

当前两者已经同步，因此不需要修改分支名称。
